# Agile Planning

## User Stories
1. As a user, I want to register an account to access the library system.
2. As a user, I want to search for academic resources to find relevant materials for my studies.
3. As a user, I want to borrow books so that I can read in my own time.
4. As a user, I want to return borrowed books to keep my account in good standing.
5. As a user, I want to review borrowed books to help others find relevant resources.
6. As a user, I want to create reading lists to keep track of items I wish to explore.
7. As a user, I want to set reminders for due dates on borrowed items.
8. As a user, I want access to user guides for help with using the system.
9. As a user, I want to provide feedback about the service to improve it.
10. As a user, I want access to my borrowing history to keep track of what I've read.
11. As a user, I want to bookmark resources to find them easily later.
12. As a user, I want to view library hours to know when I can visit.
13. As a user, I want to contact library support for assistance.
14. As a user, I want to attend workshops to understand how to utilize library resources effectively.

## Product Backlog (MoSCoW Prioritization)
### Must Have
- User account registration
- Search functionality for resources
- Borrow and return system

### Should Have
- Review system for borrowed books
- User guides access
- Feedback system

### Could Have
- Reading lists and bookmarks
- Borrowing history
- Library hours information

### Won't Have
- Contacting library support directly from the system.

## Sprint 1 Plan
### Tasks Breakdown
1. **Develop User Registration Module**
   - Design database schema
   - Create registration form
   - Implement email verification

2. **Implement Search Functionality**
   - Define search parameters
   - Create search algorithm
   - Integrate with front-end interface

3. **Build Borrow/Return System**
   - Create database for borrowed items
   - Develop loan processing logic
   - Design user notifications for due dates

## Traceability Summary
- All user stories are linked to corresponding tasks in the sprint plan, ensuring visibility and accountability. Each functionality will be tracked through user feedback in future sprints to align with user needs and improve the system.
